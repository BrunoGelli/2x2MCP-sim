## Why a reusable model is needed

Directly replaying stored Pythia rows limits detector simulation to the finite production sample. The model lets us generate more detector-MC throws while preserving the information carried by the Pythia training sample.

!!! note
    Resampling reduces detector-MC statistical noise. It does not add new independent information about the production spectrum.

## Physical emitter mixture

The model keeps separate kinematic components for every open supported parent:

```text
pi0, eta, eta', rho0, omega, phi, J/psi
```

The physical mixture comes from aggregate-summary normalization, exotic branching fractions, and production process scales—not from the raw number of stored spectrum rows.

The saved normalization is:

```text
MCP / POT / epsilon^2
```

At fixed mass, the common `epsilon²` factor cancels from the emitter fractions. Restore the requested physical charge later when computing expected yield.

## Accepted versus source stages

=== "Accepted stage — current"

    ```text
    --flux-stage accepted
    ```

    - Uses the Pythia `geometry_id=1` accepted spectrum.
    - Normalizes with `n_mcp_accepted`.
    - Provides the high-statistics input used for the first realistic detector run.
    - Does not physically reject a second time after rotation; the detector-global face check is diagnostic.

=== "Source stage — future"

    ```text
    --flux-stage source
    ```

    - Uses the pre-acceptance spectrum.
    - Normalizes with `n_mcp_total`.
    - Applies beamline transport and detector acceptance after sampling.
    - Required when material, scattering, or magnetic effects can change acceptance.

## Empirical donor + adaptive jitter

For accepted-stage models, each donor stores:

```text
log10(E)
x_at_detector_m
y_at_detector_m
Pythia theta_x, theta_y
spectrum-prescale weight
left/right module label
```

A new event is generated by:

1. selecting the physical emitter;
2. selecting a real Pythia donor with its shape weight;
3. drawing a conservative displacement inside the donor's local midpoint cell;
4. keeping energy inside the observed domain;
5. constructing left- and right-module cells independently.

The central detector gap cannot be filled by interpolation.

## Jitter scale

```text
0.0  exact weighted bootstrap
0.5  half local midpoint cell — current default
1.0  full local midpoint cell
```

Use `0.0` as a bootstrap control and compare it with `0.5` before large productions.

## Coordinates

Pythia nominal beam:

```text
(0,0,+1)
```

The sampler rotates about global `+x` to the 2×2 direction:

```text
(0,-0.0582608693,+0.9983013929)
```

No x/z permutation is used.

## First-sample beam-axis choice

The general generator supports a MiniRun5-inspired detector-plane beam-axis offset of `y=-0.42m`. The **first accepted-stage 100-event sample did not use it**.

Instead:

```text
beam axis at detector = (0,0,0)m
```

This maps the Pythia accepted-window center to the detector center. The real offset is deferred until a pre-acceptance/source model can treat acceptance self-consistently.

## Beamline model

The current model is:

```text
straight_line_v0
```

Between the Level-0 target and local injection, it applies no:

- energy loss;
- multiple scattering;
- magnetic deflection;
- attenuation;
- hard material interaction.

The approximation is named in every sample summary and macro so it can be replaced later without changing the source-model or EDepSim interface.

## Required model-build audit

The v3 builder independently sums from input ROOT `mcp_summary` trees:

```text
n_events_generated
n_mcp_total
n_mcp_accepted
```

and compares them with the supplied aggregate summary for each selected mass/emitter/mode/geometry key.

A mismatch fails by default. The audit is written to:

```text
input_summary_audit.csv
```

Do not bypass this check unless the mismatch is understood and documented.
